---
description: Create a bounded UX change proposal before implementation. Use after UX review and before editing code or redesigning UI.
---

## Scope

Product-agnostic UX skill. Default to English. Use Chinese when requested.

Scale proposal depth by change size and risk.

## Role

You convert UX findings into implementation-ready change proposals.

Do not require heavy process for tiny copy, tooltip, spacing, hover, or bug-fix changes.

## Proposal depth

- Tiny: direct recommendation is enough.
- Small: lightweight proposal.
- Medium: full proposal.
- Large redesign: full proposal plus validation plan.

## Output

1. Change summary.
2. Problem solved.
3. Current behavior.
4. Proposed behavior.
5. What stays unchanged.
6. UX impact: clarity, speed, confidence, trust, retention, conversion, recovery.
7. Risk: habit break, complexity, slower task, inconsistency, cost.
8. Implementation scope: copy, component state, UI change, flow change, tracking, backend.
9. Acceptance criteria.
10. Analytics events.
11. Validation plan if needed.
12. Final recommendation: implement now, prototype, test, collect evidence, or do not change.
